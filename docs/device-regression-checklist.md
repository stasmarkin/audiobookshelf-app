# Physical-device regression checklist

For the current physical test device, the Samsung Galaxy S26 Ultra (One UI). Earlier rounds named a Galaxy S22 Ultra; that is historical. Run it against the release-package build of whatever is about to be distributed, installed in place over the previous build. Capture `adb logcat` and a Diagnostics export (level Debug) for every run.

Items marked **emulator-covered** already pass on an AOSP API 35 emulator (see the note below). They still need hardware confirmation, because Samsung's power management, media stack and Bluetooth behave differently. Record results in `docs/release-process.md` next to the build's versionCode.

## Test data

- A collection or series of at least 4 downloaded audiobooks, including a very short one (under 1 minute) so queue transitions happen quickly. Also a 12-item queue, to match the earlier approved S26 Ultra run.
- One book that is not downloaded (to test streaming past a gap), and one multi-file book.
- A wired headset or USB-C headset with a play button, and a Bluetooth headset or car kit.

## 1. Install and startup

1. Install in place over the previous build. The app starts, the existing downloads are listed, and the Diagnostics log shows no "invalid download queue" line on a healthy install.
2. Cold start after a reboot. There's no auto-play, and no restore happens until Play is pressed.
3. Expired sign-in (test server with a short `ACCESS_TOKEN_EXPIRY`, `docs/authentication.md`):
   - after the token expires, open a busy screen such as Home. It loads without a sign-in screen, and the server logs one `/auth/refresh`;
   - with the phone offline when the token expires, you stay signed in, and going back online recovers.

## 2. Queue and continuous playback (emulator-covered)

1. Start the collection in the middle. Up Next shows the right order and current item.
2. Let a short book end with the screen locked and the app in the background. Native playback advances to the next book, and Up Next is correct on return.
3. Include an undownloaded book. It streams in its place, and the cellular prompt appears if the cellular setting requires it.
4. Reorder and remove Up Next items while playing.

## 3. Swipe-away and restoration (emulator-covered through the widget key code only)

1. Swipe the app away **while playing**. Playback continues, and reopening reattaches to the same session and Up Next.
2. Pause, then swipe away. The notification goes away and the session stays resumable.
3. Widget Play: the session is rebuilt with the same book, position (within the last progress save), speed and Up Next, and resumes.
4. Repeat step 3 in Airplane Mode with a downloaded book.
5. Repeat step 3 after the process is gone. On Samsung, wait for it to be killed or use `adb shell am kill`.
6. **Wired headset button, and Bluetooth Play, after step 2.**
   - `KEYCODE_MEDIA_PLAY`, `KEYCODE_HEADSETHOOK` and `KEYCODE_MEDIA_PLAY_PAUSE` must all restore the session, with the service gone and with the process killed. Fixed on `plus` after v0.15.1: these keys act on key-up, and the key-down no longer releases the placeholder foreground or stops the service before the key-up arrives (`MediaButtonLifecycle`). Before the fix, Play and Headset Hook did nothing there and could crash the app with `ForegroundServiceDidNotStartInTimeException`.
   - Check `adb logcat -b crash` stays empty and no "still waiting for start foreground" line appears.
   - Record which key code each real headset or car kit sends (`adb logcat | grep handleCallMediaButton`) and whether it restores.
7. Close the player with the X, then press widget Play. Nothing restores.
8. Force stop in Android Settings, then press Play. Nothing starts. Reopen the app normally.

## 4. System media surfaces

1. The media notification and lock-screen controls show play/pause, jump back and jump forward, and they update when playback advances to the next queue item.
2. Samsung's Now Bar or media card (One UI) matches the playing book, and its controls work.
3. Bluetooth disconnect pauses playback, and a reconnect doesn't resume it on its own.
4. Android Auto, if available: browsing and playback start. The root shows Continue, Recent, Libraries and Downloads at once, online and in airplane mode; a book in Continue shows the same progress as in the app. See section 9 for the offline checks.
5. A downloaded book whose cover file is missing or damaged still restores and plays. Rename or truncate the cover after closing the app, then restore with the widget or a media key. The notification and lock screen show the Audiobookshelf+ artwork, and `adb logcat -b crash` stays empty. Fixed on `plus` after v0.15.1 (`CoverArt`).

## 5. Downloads

1. Download a multi-file book. Swipe the app away mid-download, and separately let the process be killed mid-download. On relaunch the queue is restored and the download finishes. Parts that weren't finished restart from byte 0 after a restore; that is intended.
2. An external SAF folder download works. Revoke the folder's permission, and the download reports lost access instead of failing silently.
3. Rescan Folder recognizes the existing downloads.

## 6. Long-running and background

1. Two or more hours of continuous playback with the screen off, the device unplugged and default battery settings. There are no stops, and progress syncs.
2. Repeat with the app set to "Restricted" or "Optimized" in Samsung battery settings, and note any difference.
3. A sleep timer during a queue transition.

## 7. Diagnostics and privacy

1. View, Mark, Save (system file picker), Share and Clear all work.
2. An exported log contains no server host, username, token, device path or `content://` URI.
3. Raw `adb logcat` (debug build included) contains no token, `Authorization`/`x-refresh-token` header, refresh-token cookie, server connection config or username. Capacitor's own logging is off (`loggingBehavior: "none"`), and the app's logcat copies (`DLog`, `AbsLogger`) go through the same sanitizer as the diagnostic log.

## 8. Languages and UI

1. Switch to Korean, Arabic, Hebrew and Slovak. Screens stay readable, and fork-only strings fall back to English. Arabic and Hebrew are not mirrored right-to-left, which is expected for now.
2. Font size at 200%: Settings → Diagnostics and the login screen stay usable. The login screen also works with the keyboard open.
3. RICE (Settings → Appearance, `docs/rice-customization.md`), on a Samsung phone:
   - **Follow device:** with "Device colors and light/dark" selected, change the One UI Color palette and switch dark mode. The app follows after returning to it, and a placed widget follows at its next update.
   - **Starter and custom presets:** a starter and a custom preset color the widget (Android 12+), the status/navigation bar areas and the app.
   - **Back to built-ins:** choosing a built-in or turning RICE off restores the exact built-in look everywhere.

## 9. Offline and server reachability

Needs a test server on the LAN that you can stop and start (for example its container), and a Wi-Fi connection that stays up.

1. **Server stopped, Wi-Fi alive:** open Home and leave it. Stop the server process or container (the host stays up, so its socket closes at once). Within 15 seconds, without a restart or a tap, the app-bar indicator changes to "server unreachable" (cloud with a slash, warning color). Tapping it shows the message with Retry and Cancel; Retry checks the server at once.
2. **Server host switched off, Wi-Fi alive:** with Home open, power off or unplug the server machine, so the socket goes silent instead of closing. The indicator changes to "server unreachable" once the socket times out: socket.io-client waits the server's `pingInterval` + `pingTimeout` (engine.io server defaults 25 + 20 s; not checked against the Audiobookshelf server's settings), then the `/ping` check takes up to 5 s, so about 45–60 seconds.
3. **Server back:** start the server again and touch nothing. Within one retry step (5, 10, 30, 60 seconds, then every 5 minutes; Retry in the indicator dialog or returning to the app checks at once) the indicator shows online again, Home and the other tabs load, and the Diagnostics log shows the local listening sessions syncing.
4. **Cold start with the server stopped:** force-stop the app, stop the server, start the app. The indicator shows "server unreachable" (not "no network") and no sign-in screen opens. Start the server: the app signs in by itself and the library loads.
5. **Airplane mode on a cold start:** the indicator shows "no network" (Wi-Fi with a slash), and the indicator raises no toasts. Turning airplane mode off with the server running brings the indicator back to online.
6. **Bookmarks in airplane mode:** while playing, turn airplane mode on. Create, rename and delete bookmarks: no toast appears, the list updates at once, and the indicator says how many changes wait to be sent.
7. **Bookmarks on a cold start without a network:** force-stop the app with airplane mode on and start it again. The bookmarks of the playing book are in the list.
8. **Offline bookmarks reach the server:** turn airplane mode off. The indicator shows syncing, then online; the bookmarks made offline are in the server's web client and on a second device, and the deleted ones are gone there.
9. **Bookmark deleted elsewhere:** delete a bookmark in the server's web client, then tap the indicator and Sync now. The bookmark disappears from the phone.
10. **Update from the previous version, online:** after installing over the previous version, all bookmarks from the server are in the list.
11. **No full sync on a short trip to the background:** play, switch to another app for a minute and come back. The Diagnostics log has no new `SyncEngine` `Reconcile` entry for this return.
12. **Sync after a long server outage in the background:** put the app in the background, stop the server for 20 minutes, start it, then open the app. The Diagnostics log shows exactly one new `SyncEngine` `Reconcile` entry.
13. **Finished and reset in airplane mode:** with airplane mode on, mark a book that is not downloaded finished, mark a downloaded book and a downloaded podcast episode finished, and reset the progress of a third book. No error toast appears (the reset still confirms "Your progress was reset": it is done on the device), each change shows at once (also on the downloaded item's own page), and the indicator counts the waiting changes. Turn airplane mode off: the server's web client and a second device show the same values.
14. **Listening on another device:** later, listen to one of those books on the second device. Back on the phone (Sync now or reopening the app), its progress follows the second device.
15. **Offline listening is kept:** in airplane mode, listen to a downloaded book for a few minutes, then turn airplane mode off. Its position is not moved back by an older position on the server, and the server's web client shows the phone's position after the sync.
16. **E-book position offline:** in airplane mode, read a few pages of a downloaded e-book, then turn airplane mode off. The server's web client opens it at that page.
17. **Revoked session:** with the app open, revoke its session on the server (change the password in the web client). The app stays on the same page with the selected library, bookmarks and progress; the indicator says "sign in again". Mark something finished: it waits. Tap the indicator: the sign-in form opens for that server with the "session expired" message; after signing in, the waiting change reaches the server.
18. **Streamed listening while the server is down:** stream a book that is not downloaded and note the server's listening time for it. Stop the server for 2 minutes and keep listening to what the player buffered (or play a downloaded book), then start the server. After the sync, the server's listening sessions show the streamed session and a second, offline session; together they add the time actually listened within 15 seconds, and the streamed session was not overwritten by the offline one.
19. **Downloaded book in airplane mode:** listen to a downloaded book for 10 minutes in airplane mode, then turn airplane mode off. The server's web client shows the phone's position and the listening session after the sync.
20. **Stream, server stopped:** stream a book that is not downloaded, then stop the server. When the buffer runs out (about 6 seconds to over a minute) the player pauses, stays open and shows "Waiting for server" instead of "Playback Failed". Start the server and touch nothing: playback continues by itself at the same position. Repeat with Wi-Fi switched off and on instead of the server.
21. **Waiting, then Pause, seek or Play:** while it waits, press Pause, seek, then start the server: it resumes paused at the new position. Press Play while the server is still down: it keeps waiting (and checks the server at once).
22. **Downloaded book never streams:** with a downloaded book, start it from the card, the item page, the Continue shelf, a series queue, Android Auto and the widget, once with the server running and once in airplane mode. The Diagnostics log shows a local start (`startItem: downloaded item`, `preparePlayer: Playing local item`) every time.
23. **Download while streaming:** stream a book and start its download. When the download finishes, playback continues from the file without a jump (±2 s); the queue is kept.
24. **Queue reaches an undownloaded book offline:** play a series queue whose next book is not downloaded, turn airplane mode on and let the current book end. The player waits on that book with "Waiting for server" and does not skip it; after turning airplane mode off it continues with that book.
25. **Early end of a stream:** while streaming, cut the network mid-file several times. The queue never advances past a book because of the cut; the Diagnostics log has no `STATE_ENDED of a stream … before its end` warning (if it has one, report it with the log).
